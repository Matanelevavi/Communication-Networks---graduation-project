      How a forecast reaches you
      
        
      This site is a host on a small simulated network. Each request takes the path a new machine takes when it joins one.
      
      
      
      
        
        
      1. 1
        DHCP
        The site asks for an address: Discover, Offer, Request, Acknowledge. A backup server answers if the primary is down.
        2. 
        
      2. 2
        DNS
        It resolves weatherwear.local through a local DNS server, and caches the answer for the TTL the server sets.
        3. 
        
      3. 3
        TCP / RUDP
        Your request travels over TCP, or over RUDP: sequence numbers, CRC32, retransmission, congestion control and flow control, written from scratch on top of UDP.
        4. 
        
      4. 4
        App server
        The server fetches live weather from Open-Meteo, and writes advice for each person, with Gemini when a key is set and with local rules otherwise.
